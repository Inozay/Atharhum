# Source, knowledge and safety protocol

## 1. Source registry
Every production knowledge record should have: Source ID, title, author/publisher, URL or document reference, publication/access date, language, source type, rights/license, verification status and reviewer.

## 2. Source hierarchy
1. Primary/institutional sources where appropriate.
2. Recognized educational or academic references.
3. Curated secondary sources with explicit review.
4. General web material is not automatically trusted.

## 3. Retrieval
Sensitive answers must retrieve only from approved records. The answer layer should show citations and the content identity used to generate the response.

## 4. Human review
New sources, translations, cultural adaptations and sensitive answers should be reviewable by a qualified human. Low-confidence or conflicting evidence should trigger escalation rather than a fabricated answer.

## 5. AI boundary
Atharuhum is not an autonomous Mufti. It is a knowledge and experience layer: retrieval, navigation, explanation, localization, learning-path generation and impact intelligence.

## 6. Privacy
Basic analytics use anonymous/session identifiers. The platform should not infer or classify sensitive religious attributes. Impact is measured through observable engagement and learning events.

## 7. Demo disclaimer
The sample source URL and knowledge records in this repository are illustrative placeholders for the hackathon demo. They must be replaced with reviewed, licensed, authoritative sources before production publication.
